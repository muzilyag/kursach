# Документация по тестированию Frontend-части

В данном разделе описана архитектура тестирования клиентской части приложения (SPA на Vue 3). Проект покрыт более чем 130 изолированными модульными и интеграционными тестами с общим покрытием кода (Coverage) около **90%**.

## Стек тестирования
* **Тестовый фреймворк:** `Vitest` (совместим с экосистемой Vite)
* **Утилиты для компонентов:** `@vue/test-utils`
* **Виртуальный DOM:** `jsdom`
* **Инструмент покрытия:** `@vitest/coverage-v8`

---

## Архитектура тестов и изоляция

Для обеспечения высокой скорости выполнения и независимости тестов применяется мокирование внешних зависимостей:

1. **Изоляция API:** Все запросы к бэкенду перехватываются с помощью `vi.mock('@/services/api')`. Тесты проверяют реакцию интерфейса на различные ответы сервера (успех `200 OK`, ошибки `400/500`, падение сети).
2. **Изоляция Роутера:** Навигация и перенаправления тестируются с помощью заглушек `vue-router` (`vi.mock('vue-router')`), что позволяет отслеживать вызовы `router.push()` без реального монтирования страниц.
3. **Глобальные объекты:** Системные вызовы, такие как `window.alert`, `window.confirm` и `localStorage`, переопределяются для каждого теста в хуке `beforeEach`, чтобы избежать побочных эффектов.
4. **Асинхронность:** Реактивность Vue и асинхронные вызовы API синхронизируются в тестах с помощью утилиты `flushPromises()`.

## Покрытие модулей

| Модуль | Описание проверяемых сценариев |
| :--- | :--- |
| **API Сервис** (`api.spec.ts`) | **Покрытие 100%.** Проверка внедрения JWT-токенов (`Authorization: Bearer`), логика обработки `401 Unauthorized` (удаление токена) и `403 Forbidden`. Эмуляция всех GET, POST, PUT, DELETE запросов и скачивания Blob-файлов (PDF/CSV). |
| **Views (Страницы)** (`*View.spec.ts`) | Жизненный цикл страниц: логин, дашборд, каталог, профиль, отчеты и подписки. Проверка рендеринга таблиц, графиков, открытия модальных окон, а также реакции UI на негативные сценарии (ошибки API, отмена действий пользователем). |
| **Components** (`DataTable`, `Pagination`...) | Изолированное тестирование переиспользуемых UI-компонентов. Проверка генерации событий (`emits`), граничных случаев (пустые массивы, 0 записей), блокировки кнопок (`disabled`) и отрисовки слотов. |
| **Utils & Composables** | Проверка чистых функций форматирования (даты, валюты, длительности), валидации email и бизнес-логики вычисления возраста. Строгое тестирование граничных сценариев (NaN, пустые строки). |

## Как запустить тесты

Все команды выполняются из директории `frontend/`.

**1. Быстрый запуск всех тестов:**
```bash
npm run test
```
**2. Запуск тестов с генерацией отчета о покрытии (Coverage):**
```bash
npm run test:coverage
```
После выполнения команды детальный интерактивный HTML-отчет будет доступен в папке frontend/coverage/index.html.
**3. Запуск тестов в режиме наблюдения (Watch mode) при разработке:**
```bash
npm run test:watch
```
**4. Запуск тестирования конкретного файла:**
```bash
npx vitest tests/views/DashboardView.spec.ts
```
